How to check BibTeX references for retractions

A free single-file check against Crossref, with a worked example that uses a public retraction notice.

On 2025-01-29 Crossref announced that Retraction Watch retractions are available in its REST API, so tools that look up works can surface those notices alongside publisher updates (Crossref, 2025-01-29). If a .bib file still cites a retracted work, that notice is easy to miss until something looks it up.

Worked example

Take this BibTeX entry. Its DOI is a real Crossref work that has a retraction recorded in Crossref (via Retraction Watch). The entry below uses placeholder author and title fields on purpose; the check keys on the DOI.

@article{example1998,
  author = {Example, A.},
  title  = {An example entry for a DOI check},
  journal = {Example Journal},
  year   = {1998},
  doi    = {10.1016/S0140-6736(97)11096-0}
}

The public Crossref record for that DOI is https://doi.org/10.1016/s0140-6736(97)11096-0. Crossref lists a retraction update whose notice is https://doi.org/10.1016/s0140-6736(10)60175-4 (dated 2010-02-06 in the Crossref metadata). Cite Ledger reports that as a retraction finding and links the notice; it does not name or characterise the authors of the retracted work.

Steps (free tier)

  1. Install Cite Ledger from the VS Code Marketplace or Open VSX.
  2. Open your .bib file.
  3. Run Cite Ledger: Check References in This File from the Command Palette (or use the checklist button in the editor title bar).
  4. Open the Problems panel. Each finding names its claim and links to its evidence.

Single-file checks are free; Pro is a one-time licence.P6 Retraction flags are included on the free single-file path.

  • Flags retractions, corrections and expressions of concern recorded in Crossref, including Retraction Watch data.P2
  • Runs on your machine and sends only the reference details it looks up to Crossref.P5

Limits

  • Does not check DOIs registered outside Crossref, for example DataCite.L1
  • Crossref's retraction data can miss some retractions.L2
  • 'Unverified' means no matching record was found, not that the reference is fabricated.L3
