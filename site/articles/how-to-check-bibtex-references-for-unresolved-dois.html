How to check BibTeX references for unresolved DOIs

A free single-file check against Crossref, with a worked example in which one mistyped character hides a public retraction notice.

DOIs are often copied from formatted pages, and Crossref has written about how hard it is to tell where a DOI ends in such text: "Is the period at the end of the line part of the DOI or part of the design?" (Crossref, 2015-08-11). A DOI in a .bib file that gained or lost a character points at nothing, and every check that keys on it, including a retraction check, then has nothing to look up.

Worked example

Take these BibTeX entries. The first two are meant to cite the same work, a real Crossref work with a retraction recorded in Crossref (via Retraction Watch); the first has dropped one digit from its DOI. The third is a preprint whose DOI is registered with DataCite. Author and title fields are placeholders on purpose; the check keys on the DOI.

@article{typo1998,
  author  = {Example, A.},
  title   = {An example entry for a DOI check},
  journal = {Example Journal},
  year    = {1998},
  doi     = {10.1016/S0140-6736(97)1109-0}
}

@article{fixed1998,
  author  = {Example, A.},
  title   = {An example entry for a DOI check},
  journal = {Example Journal},
  year    = {1998},
  doi     = {10.1016/S0140-6736(97)11096-0}
}

@misc{preprint2017,
  title = {An example preprint entry},
  year  = {2017},
  doi   = {10.48550/arXiv.1706.03762}
}

Cite Ledger 0.1.1 reports these findings, among others:

refs.bib:1 typo1998 [P1 doi-not-found] DOI 10.1016/s0140-6736(97)1109-0 does not resolve in Crossref.
refs.bib:9 fixed1998 [P2 retraction] Retraction recorded in Crossref for 10.1016/s0140-6736(97)11096-0 (2010-02-06): notice 10.1016/s0140-6736(10)60175-4. Recorded by Retraction Watch.
refs.bib:17 preprint2017 [P1 other-agency] DOI 10.48550/arxiv.1706.03762 is registered with DataCite, not Crossref. Cite Ledger does not check DOIs registered outside Crossref (L1).
  • The mistyped DOI has no record in Crossref and no registration agency, so it is flagged as not resolving. The finding links to api.crossref.org and doi.org, so you can see for yourself. Nothing else can be checked for that entry, so the retraction stays hidden until the DOI is fixed.
  • The corrected DOI is the public Crossref record 10.1016/s0140-6736(97)11096-0. Its retraction notice is 10.1016/s0140-6736(10)60175-4, dated 2010-02-06 in the Crossref metadata. Crossref also records a correction for it. Because the example uses placeholder author and title fields, this entry also gets title and first-author differences; your real entries should not.
  • The DataCite DOI is not in Crossref, so Cite Ledger names the agency that registered it instead of calling it unresolved, and does not check the work further.

Steps (free tier)

  1. Install Cite Ledger from the VS Code Marketplace or Open VSX.
  2. Open your .bib file.
  3. Run Cite Ledger: Check References in This File from the Command Palette (or use the checklist button in the editor title bar).
  4. Open the Problems panel. For each DOI that does not resolve, open its doi.org link, compare the DOI with the publisher's page, fix the entry and check the file again.

Single-file checks are free; Pro is a one-time licence.P6

  • Flags references whose DOI does not resolve in Crossref.P1
  • Flags retractions, corrections and expressions of concern recorded in Crossref, including Retraction Watch data.P2
  • Runs on your machine and sends only the reference details it looks up to Crossref.P5

Limits

  • Does not check DOIs registered outside Crossref, for example DataCite.L1
  • Crossref's retraction data can miss some retractions.L2
  • 'Unverified' means no matching record was found, not that the reference is fabricated.L3

A DOI that does not resolve in Crossref may still be valid with an agency Crossref could not name, or the lookup may have failed; the doi.org link shows whether it resolves anywhere. More detail: limits.
